**Phase:** 2  
**Priority:** Medium  
**Depends on:** T01  
**Status:** TODO

## Goal

Structured memory at `.zforge/memory/` so agents can persist decisions and reduce context reuse across workflow steps.

## Memory Layout

```
.zforge/memory/
├── project.md        # project-level context (auto-created by init)
└── tasks/
    └── <TASK_ID>/
        ├── decisions.md    # architectural/design decisions
        ├── context.md      # relevant code context noted by agents
        └── notes.md        # freeform agent notes
```

## project.md Template

Generated by `zf init` with placeholders:

```markdown
# Project Memory

## Architecture
<!-- describe overall architecture -->

## Conventions
<!-- naming, patterns, style decisions -->

## Key Entities
<!-- core domain types -->

## External Dependencies
<!-- important libs and why chosen -->
```

## CLI Commands

### zf memory write

```
zf memory write <key> [--task <TASK_ID>]
```

- With `--task`: writes to `.zforge/memory/tasks/<TASK_ID>/<key>.md`
- Without: writes to `.zforge/memory/<key>.md`
- Reads content from stdin

### zf memory read

```
zf memory read <key> [--task <TASK_ID>]
```

- Prints file to stdout

### zf memory list

```
zf memory list [--task <TASK_ID>]
```

- Lists available memory keys

## Config

No new config fields needed — memory dir already in `PathsConfig.memory`.

## CLI Changes

Add `Memory` command to `src/main.rs`:

```rust
Memory {
    #[command(subcommand)]
    action: MemoryAction,
},

enum MemoryAction {
    Write { key: String, #[arg(long)] task: Option<String> },
    Read  { key: String, #[arg(long)] task: Option<String> },
    List  {              #[arg(long)] task: Option<String> },
}
```

## New Module

`src/cli/memory.rs`:

```rust
pub fn run_write(key: &str, task_id: Option<&str>) -> Result<()>
pub fn run_read(key: &str, task_id: Option<&str>) -> Result<()>
pub fn run_list(task_id: Option<&str>) -> Result<()>
```

## Integration with MCP tools

`write_memory` and `read_memory` MCP tools (T04) use the same path logic — extract into `src/memory/mod.rs` shared by both CLI and MCP.

## init Scaffold Change

`zf init` (and `zf init --pack golang-tdd`) creates:
- `.zforge/memory/project.md` (template)
- `.zforge/memory/tasks/` (empty dir)

## Test Cases

- `zf memory write project` reads from stdin, writes to `.zforge/memory/project.md`
- `zf memory read project` prints content
- `zf memory write decisions --task TASK-1` writes to tasks dir
- `zf memory list` shows all top-level keys
- `zf memory list --task TASK-1` shows task-scoped keys
- Missing key on read → clear error "memory key not found: <key>"
- `zf init` creates `project.md` with template content
