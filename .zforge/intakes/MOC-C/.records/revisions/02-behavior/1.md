# MOC-C — Behavior

## Tình huống

Ví dụ dùng chung: handover `HANDOVER-001` gồm A, B (phụ thuộc A), C (phụ thuộc
B), D (độc lập). Thứ tự trong manifest: A, B, C, D.

### Bình thường

1. **Chạy cả feature** (REQ-001, REQ-002, REQ-004). `zforge run HANDOVER-001`:
   - A: run từ baseline → `verified`, candidate `a1`, commit `ca`.
   - B: run có `start_commit = ca`, nguồn `A:RUN-001` → `verified`, commit `cb`.
   - C: từ `cb` → `verified`, commit `cc`. D: từ baseline → `verified`, `cd`.
   - Tích hợp: worktree từ baseline, merge `cc` và `cd` (các task không task
     nào khác phụ thuộc), chạy lệnh "Kiểm chứng tích hợp" → pass, candidate `i1`.
   - Lệnh in từng bước và kết thúc bằng `feature verified (integration RUN-005)`.
   Exit 0.

2. **Chạy một task có dependency** (REQ-003). `zforge run HANDOVER-001 --task B`
   sau khi A đã verified: B chạy từ commit của A. Trước khi A verified: từ chối
   `B depends on A, which has no verified run in HANDOVER-001`; không tạo gì.

3. **Xem trạng thái feature** (REQ-007). `zforge run status HANDOVER-001`:
   ```
   A  verified   RUN-001  candidate a1
   B  verified   RUN-002  from A:RUN-001
   C  running    RUN-003
   D  waiting
   integration  waiting (C, D)
   ```
   Mọi dòng suy từ `events.jsonl` của các run; không đọc file trạng thái nào khác.

### Biên

4. **Task không có dependency và không có task nào khác**: một task, rồi kiểm
   chứng tích hợp trên chính output của nó. Handover một task vẫn có bước tích
   hợp, vì "Kiểm chứng tích hợp" có thể khác test của task.

5. **Nhiều dependency** (REQ-002). E phụ thuộc B và D: worktree của E là merge
   của `cb` và `cd` trên nhánh mới; `run.yaml` ghi cả hai nguồn. Merge xung đột
   → run E `failed` với lý do `dependency outputs conflict: B, D` và danh sách
   file xung đột; không chạy agent; task phụ thuộc E bị chặn.

6. **Task đã có run verified** khi chạy lại cả feature (REQ-008): bỏ qua, in
   `A verified (RUN-001), skipped`. Task có nhiều run verified: dùng run
   verified mới nhất.

7. **Task đang có run chạy** (REQ-008): `zforge run HANDOVER-001` thứ hai trong
   lúc cái đầu còn chạy → từ chối `HANDOVER-001 is being run by pid N`.

### Lỗi

8. **Task bị chặn** (REQ-005). A `blocked (budget)`: B, C không chạy, in
   `B waiting on A (blocked)`; D vẫn chạy tới `verified`; tích hợp không chạy.
   Lệnh kết thúc với exit 1 và tóm tắt: task nào verified, task nào bị chặn bởi
   task nào.

9. **Tích hợp fail** (REQ-004). Mọi task verified, lệnh tích hợp fail: run tích
   hợp `failed` với output test; feature không `integration_verified`; không gọi
   agent để sửa ở bước tích hợp (xem Quy tắc 6).

10. **Amendment giữa chừng**. C ghi change request → C `blocked: amendment`.
    Task không phụ thuộc C (A, B, D) không bị ảnh hưởng; tích hợp bị chặn.

### Hồi phục

11. **Ngắt rồi chạy lại** (REQ-008). Kill lúc B đang chạy. `run status` thấy B
    `failed (interrupted)`. Chạy lại `zforge run HANDOVER-001`: A bỏ qua, B chạy
    một run mới (`retry_of` run cũ, budget còn lại của B), rồi tiếp C, D.

12. **Handover mới sau amendment** (REQ-006). Người dùng sửa và chốt C, handover
    `HANDOVER-002`. Chạy nó: A, B tái dùng từ `HANDOVER-001` (in `A reused
    RUN-001`), C chạy từ commit của B, D tái dùng, rồi tích hợp. Nếu 03-solution
    cũng đổi thì không tái dùng gì: stage là một phần hợp đồng của mọi task.

## Quy tắc nghiệp vụ

1. Output của một task là **commit mà run `verified` đã kiểm chứng**, không phải
   đầu branch: commit agent làm sau khi verify không được tính.
2. Task xuất phát từ baseline nếu không có dependency; một dependency → commit
   của nó; nhiều dependency → merge các commit đó.
3. Tích hợp xuất phát từ baseline và merge output của mọi task không bị task nào
   khác trong handover phụ thuộc (các "lá" của đồ thị); output của task trung
   gian đã nằm trong đó.
4. Chỉ task được handover mới chạy. Dependency ngoài handover đã bị readiness
   chặn từ Mốc A; không có đường nào khác để một task thiếu dependency chạy.
5. Tái dùng đòi hỏi trùng hash của: file task, bốn stage, và file task của mọi
   dependency bắc cầu. Thiếu một điều kiện là chạy lại; không có "gần giống".
6. Bước tích hợp không gọi agent. Tích hợp fail nghĩa là hợp đồng giữa các task
   có vấn đề, việc sửa đi qua amendment như mọi thay đổi hợp đồng.
7. Budget vẫn theo (handover, task). Tích hợp không tốn budget agent.
8. Trạng thái feature luôn suy ra, không bao giờ được lưu.
9. `integrated` chỉ đúng khi commit tích hợp là tổ tiên của branch baseline hiện
   tại; khi người dùng merge theo cách khác (squash, rebase), knowledge nói
   `integration_verified`, không đoán.

## Hành vi cũ cần bảo toàn

- `zforge run HANDOVER-001 --task A` cho task không dependency chạy giống hệt
  Mốc B, kể cả `run.yaml` (trường mới chỉ xuất hiện khi có giá trị).
- `run status RUN-001`, `run list`, `cancel`, `retry`, `clean`, `log`, `wait`
  giữ nguyên trên run đơn.
- `run.yaml` của Mốc B đọc được và được hiểu là xuất phát từ baseline.
- MCP: tool Mốc B giữ nguyên tên và tham số; `run_start` không có `task` thì
  chạy cả feature trong nền.
